Ticket « Texte combat Pokémon sauvage » (juin 2026, commit gba_translator `fix(fr): texte de combat sauvages`).

- **NAME_WITH_PREFIX = préfixe + nom, concaténé par le MOTEUR**, préfixe TOUJOURS devant. Le préfixe « The wild » vit à 0xA4C636 (+ copie 0x8BD155) ; « The opposing » à 0xA4C61A. Traduit « sauvage » sans espace → « sauvageNodulithe » (collé + inversé) dans TOUS les messages de combat qui utilisent ce buffer (centaines : « Le talent X de {NAME} », dégâts, stats…). Corrigé en « sauvage » + espace → « sauvage Nodulithe ». **Placer « sauvage » APRÈS le nom (« Nodulithe sauvage ») est IMPOSSIBLE en texte** : il faudrait patcher le code CFRU qui compose le buffer, et le même buffer sert joueur/adversaire (un patch global casserait « L'adversaire X »). Les messages « apparaît » (0x1F68219 etc.) n'utilisent PAS ce buffer et placent déjà « sauvage » après le nom correctement.
- **Gabarits de changement de stat** 0x3FCB5F/6A/8F/9A (rose/fell), 0xA4C200, 0x3FB7D5/EE (won't go higher/lower) : EN = `{NAME}'s {STAT}\n{VERB}` (buffers EN dans l'ordre FD0F/FD10/FD13 nom, FD00 stat, FD01 verbe). Le mapping `{...}` est POSITIONNEL (consomme les séquences EN dans l'ordre), donc `{FD00} de {FD0F}` rendait « nom de stat » (faux). Corrigé en écrivant des **tokens BRUTS dans le bon ordre** `<0xFD><0x00> de <0xFD><0x0F>\n<0xFD><0x01>` → « Vitesse de {nom}\n{verbe} ». Pas d'article (La/L') car le buffer stat est générique (élision impossible).
- Le **verbe composé** = adverbe (0x3FCB41 « sharply »/0x3FCB50 « harshly » → « fortement ») + verbe (0x3FCB4A « rose! » → « augmente ! », 0x3FCB59 « fell! » → « baisse ! »). L'espace final de « fortement » avait été perdu → « fortementaugmente ». Restaurer l'espace de bord.
- **Pop-up de talent** : « {nom}'s\n{talent} » ; le « 's » anglais (0x3FE88F, 3 octets) reste affiché (« Nodulithe's »). Trop court pour la passe inline (min_length=4) et absent du JSON → ajouter une entrée JSON avec traduction « » (espace) pour retirer le possessif.
- **Une traduction VIDE est exclue des DEUX passes** : build principal (19) saute si `not translation and raw_bytes is None` ; passe inline (apply_inline_overrides_fr) saute `if not translation` ET `byte_length < 4`. Donc impossible de « vider » un préfixe — utiliser une valeur non vide (espace).
- **Où corriger** : `output/translation/2026-06-12_translation_ready.json` (= `FR_TRANSLATION`, lu DIRECTEMENT par `make build-fr`, jamais régénéré par le build, git-tracké). combined_fr.txt est aussi mis à jour pour cohérence mais ses entrées pour ces offsets sont IGNORÉES (offsets déjà dans translated_offsets → passe inline les saute). Vérif : déréférencer le pointeur EN (`pointer_offsets` de l'extraction) dans la ROM construite car ces chaînes sont relocalisées.

- **Suffixe APRÈS le nom = RÉSOLU par code cave** (ticket B-21, juin 2026, `scripts/patch_battle_prefix_fr.py`, commit `fix(battle): append ' sauvage'/' adverse' after foe name via inline cave`). L'expansion de la chaîne de combat construit le STRING FINAL inline (préfixe, nom, puis la suite du template, SANS 0xFF entre). Sites foe-name : **0xD7BB4 (sauvage/wild) et 0xD7C94 (adverse/trainer)** = un `B 0x80D82AA/0x80D82A4` ; à ces sites **r2 = ptr nom (0x02023D6B), r6 = index écriture, r8 = base buffer, sp = buffer nom moteur**. Fix : vider le préfixe (1er octet→0xFF, saut de la boucle de copie) PUIS rediriger le `B` par un `BL` vers un cave (0x1D89C/0x1D908) qui : copie le nom depuis [r2], ajoute le suffixe 8 octets INLINE (pas de 0xFF), écrit 0xFF dans [sp] (la recopie nom du moteur devient no-op), saute à **0x080D82E4** (point de convergence après formatage → gender + suite du template). `ADD r5,sp,#8` car PUSH {r4,r5} décale sp de 8.
- **Deux pièges de cave qui ont échoué avant** : (1) écrire un `0xFF` terminateur après le suffixe → **tronque le reste du message** (l'expansion est inline, pas un buffer staging) ; (2) garder sur `[r2]==0xFF` (jamais vrai pour un vrai nom → suffixe jamais écrit) + `movs r6,#8` absolu qui corrompt l'index. Garde-fous dans `tests/e2e/test_battle_adverse_suffix.py`.
- **Vérif émulateur headless** : `mgba --script x.lua` avec `SDL_VIDEODRIVER=dummy` lit la mémoire / charge savestate / `emu:setKeys()` bouge le joueur — MAIS déclencher un combat sauvage est instable (pas d'herbe accessible depuis la .ss2 ; mGBA headless crashe ~5000 frames de marche). Cave vérifiée par désassemblage capstone des octets générés, pas en combat live.
