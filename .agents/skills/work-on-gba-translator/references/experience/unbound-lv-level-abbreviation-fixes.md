Deux bugs distincts trouvés en corrigeant l'abréviation de niveau EN "Lv." → FR "N." (issue GitHub #48) :

1. **Offset combined_fr.txt doit matcher exactement la clé de l'extracteur, padding en tête exclu.** L'en-tête de l'écran d'échange (Salle Union : "Name{icon}Wanted{icon}Offer{icon}Lv.") avait une entrée `combined_fr.txt` à `0x459375` (incluant 3 octets `00 00 00` d'espaces de tête) mais l'extracteur (`output/extracted/extracted_texts/patchedfrenchrom_texts.json`) indexe cette même chaîne à `0x459378` (3 octets plus loin, sans les espaces). Résultat : cette entrée n'a **jamais** matché (`missing_en` dans `prepare_fr_json.py`), donc toute la ligne restait 100% anglaise dans la ROM depuis toujours — pas juste "Lv." mal traduit, mais rien traduit du tout. Toujours vérifier la clé réelle dans le JSON d'extraction avant de corriger une entrée qui semble "déjà là mais fausse" — elle peut être un no-op complet. Fix : ré-ancrer l'entrée à `0x459378` sans les espaces de tête (le format `combined_fr.txt` les aurait de toute façon supprimés : `LINE_RE` dans `prepare_fr_json.py`/`apply_combined_fr.py` mange tout `\s*` après les deux-points).

2. **Table d'en-têtes partagée Panthéon/Résumé (No./Lv./Nom/IDNo., région ~0x4160EA)** : `Lv.` n'avait **aucune** entrée dans `combined_fr.txt` (contrairement à `Nom`/`IDNo.` qui existaient déjà) — ajout d'une entrée `0x4160f1: N.` en no-pointer in-place (budget ≤7 octets EN, largement suffisant). Le patch ne remplace que le préfixe utilisé ; les octets EN restants du slot (`Lv. ` + terminateur) restent en mémoire morte juste après, visibles si on dump séquentiellement le ROM par terminateurs `0xFF`, mais jamais lus par le jeu (lecture par offset fixe, pas par balayage séquentiel) — comportement normal, cf. [[unbound-nopointer-inplace-budget]].

3. **RÉSOLU (B-234) : le "Lv" de la liste équipe (menu START → Pokémon, ex. "Lv10") = extra-symbole #5 `F9 05` dans une 2e copie de `gText_Lv` @0x26051C (3 ptrs).** Fix = réécrire `F9 05`→`C8 AD` ("N.") — mêmes 2 octets que le fix Résumé de B-508 (@0x416223), mais `summary_lv_labels.py::_patch_header` ratait 0x26051C car il exigeait un `FF` devant (0x26051C est précédé de 0x08). Généralisé `_patch_header` pour patcher toute chaîne `F9 05 FF` pointée (word-aligned) → couvre 0x416223 (Résumé) + 0x26051C (liste équipe). Vérifié en jeu : « N.10 ». **Le glyphe-ligature cp 0x05 @0x1ECFA0 (party_lv_label.py, F-113/B-236) est INERTE pour la liste équipe** : il est déjà « N. » dans le build alors que la liste montrait « Lv » jusqu'à ce fix-chaîne (le code de niveau lit la chaîne 0x26051C + blit le graphique extra-symbole @0x45a010, PAS 0x1ECFA0). Localisé via watchpoints mGBA (`bridge.lua` WATCHPOINT ; trace : write VRAM tuile-fenêtre → write buffer EWRAM 0x2002388 → glyph buffer 0x2020010 → read ROM chaîne @0x416222/0x26051C + graphique @0x45a010). PIÈGE probe : `loadStateSlot(2)` lit `<basename-rom>.ss2` — copier la savestate à côté du ROM patché.
   [ancien texte, contexte négatif toujours valide] Décompo pixel : "L" majuscule 7px + "v" minuscule 4px composité au runtime dans les tuiles-fenêtre BG0. Décompo pixel (dump VRAM BG) : "L" majuscule 7px + "v" minuscule 4px + chiffres, composité au runtime dans les tuiles-fenêtre BG0 (screenblock 31, tuiles ~0x8d/0x9b/0x9c). Éliminé empiriquement via boucle « patch ROM → probe en jeu » (`scripts/probe_party_menu.mts`, savestate slot 2) : ce n'est PAS une chaîne CFRU pointée (scan inverse : 3 chaînes "Lv*" dans tout le ROM, aucune ne touche l'écran d'équipe), PAS le glyphe `{LV}`=0x34, PAS les glyphes `L`/`v`/`0`/`1` d'AUCUN des ~49 blocs LZ77 de 0x2000 (blanchis tous → "Lv10"/"30/30"/nom inchangés), PAS une tuile LZ77/brute, PAS un `gStringVar` runtime (scan EWRAM/IWRAM). Détails : `docs/analysis/party_menu_lv_investigation.md`. Le bloc `0x008001D0` (déjà dumpé, 80 tuiles) ne contient QUE le fond de carte + label PV, pas "Lv". Cf.
