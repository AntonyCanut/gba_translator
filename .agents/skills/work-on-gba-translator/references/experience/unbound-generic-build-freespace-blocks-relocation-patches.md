Verified German 3-line mission text live in the built ROM (targets land ~0x0198xxx). The `best-fit + dedup + shortest-first` packing the ticket cited is ALREADY in shared `src/core/text_reinserter.py` (both builds use it) — the lever was the flag, not the packer. Porting FR post-build patches to a generic-build language (IT via `build_language.py it`, DE) splits cleanly by whether the patch **relocates text into free space**:

- **In-place / EN-restore patches port trivially** via a thin `scripts/patch_<name>_it.py` wrapper that delegates to `patch_<name>_fr.py` through `src/i18n/fr_patch_delegate` (DE has `de_patch_delegate`), pointed at Italian data. Verified working: `summary_labels, battle_string_templates, givecs_gift_item, ability_names, tm_item_descriptions`. `build_language.py` resolves `scripts/patch_<step>_<code>.py` ahead of the shared FR branches (`_lang_patch_script`), so wrappers dispatch on just `--rom`.

- **Free-space-relocation patches FAIL wholesale** on the generic build: `19_build_translated_rom_generic.py --allow-relocate` already relocates ~11k Italian strings into the ROM's free space, leaving none for post-build passes. `dup_move_descriptions, meteorite_dialogue, mission_descriptions, move_descriptions, pokedex` all report `FAILED (free space)`, 0 relocated (move=258, pokedex=173 failed), and their **fatal exit(1) aborts the whole build** (`run(..., check=True)`). Do NOT wire them until there's a shared free-space budget between the generic builder and the post-build patches. The FR build (`make build-fr`) doesn't hit this because it has a different free-space layout.

**Why:** the generic builder is free-space-greedy; the FR-tuned relocation patches assume headroom that only the dedicated FR pipeline leaves.

**How to apply:** when a generic-language build aborts at a `patch_*_it/de.py` step, check the patch's stats for `FAILED (free space)` — it's not a wrapper bug, it's ROM free-space exhaustion. Wire only in-place patches; defer relocations. See [[unbound-multilang-build-registry]], [[unbound-fr-build-lives-in-gba-translator]]. Also: strict `verify()` in relocation patches (e.g. mission box rejecting `\l`/0xFA scroll) aborts the build on bad `combined_<lang>.txt` content — fix the entry, don't swallow.
